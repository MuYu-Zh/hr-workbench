# 企业切换与数据隔离 设计文档

- 日期：2026-08-20
- 状态：已确认
- 目标：在 `hr-workbench` 中增加“切换企业”能力，不同企业的人事数据互相隔离。

---

## 1. 背景与目标

当前 `hr-workbench` 是个人单用户、纯前端、本机存储的人事工作台。用户希望一个实例内可以管理多个企业的人事数据，并保证：

1. 不同企业的人事数据互相隔离，互不可见。
2. 用户可以随时切换当前企业。
3. 切换不影响数据安全，切换/新增/删除企业操作清晰可逆。

### 已确认决策

| 决策项 | 结论 |
|---|---|
| 隔离模型 | 每企业独立数据空间（独立 IndexedDB 数据库） |
| 存量数据 | 自动归入“默认企业”，旧数据不丢失 |
| 企业管理 | 支持新增 / 重命名 / 切换 / 删除（归档）/ 恢复 |
| 文件存储 | 同一根目录下按企业子目录落盘 |
| UI 入口 | 顶部标题栏右侧企业下拉切换 + 管理弹窗 |
| 配置隔离 | 企业相关系统参数/偏好按企业隔离，个人资料全局共享 |
| 备份恢复 | 每个企业单独备份 / 恢复 |
| 删除策略 | 删除企业仅从列表移除（归档），数据保留，可恢复 |

---

## 2. 总体架构

**核心思路：企业 = 独立数据空间，切换企业 = 切换 IndexedDB 数据库。**

- 企业注册表存 localStorage：`hr.enterprises`
- 每个企业对应独立 IndexedDB 数据库：
  - 默认企业：`hr_workbench`（兼容旧数据）
  - 其他企业：`hr_workbench_<enterpriseId>`
- `db.js` 维护“当前企业数据库连接”，切换企业时关闭旧连接、打开新库。
- 所有业务 store 定义保持不变，只是落到当前企业的数据库里。
- 企业相关配置按企业隔离；个人资料保持全局。

### 2.1 企业注册表

localStorage 键：`hr.enterprises`

```json
[
  {
    "id": "default",
    "name": "默认企业",
    "createdAt": 1234567890000,
    "archived": 0,
    "lastUsedAt": 1234567890000
  }
]
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 企业唯一标识；默认企业为 `default` |
| `name` | string | 企业名称，不允许为空 |
| `createdAt` | number | 创建时间 ms |
| `archived` | number | 0=正常，1=已归档（从列表移除但数据保留） |
| `lastUsedAt` | number | 最近使用时间 ms（可选） |

### 2.2 当前企业

localStorage 键：`hr.currentEnterpriseId`

- 默认值为 `default`。
- 切换企业时同步更新。

## 3. 数据访问层改造

### 3.1 db.js

- `db.open()` 按当前企业打开数据库：
  - `default` → `hr_workbench`
  - 其他 → `hr_workbench_<enterpriseId>`
- 新增 `db.switchEnterprise(id)`：
  1. 关闭当前数据库连接；
  2. 设置 `hr.currentEnterpriseId`；
  3. 打开目标企业数据库；
  4. 触发页面数据刷新。
- 数据库结构定义 `STORES` 和迁移逻辑保持不变。
- 新企业首次打开时自动创建全套 store。
- 切换失败时保留当前企业连接，并提示错误。

### 3.2 seed.js

- 新企业首次进入时自动写入：
  - `sys_dict` 业务字典；
  - `quick_link` 默认常用网址。
- 示例员工数据只在“默认企业”首次初始化时生成。
- 新建企业默认不写入示例员工，保持空数据空间。

### 3.3 filestore.js（文件存储模式）

- 用户选择的根目录句柄改存到全局元数据库 `hr_workbench_meta`，不随企业隔离。
- 文件落盘路径按企业分目录：

```text
你选择的文件夹/
└── <enterpriseId>/
    ├── hr-data.json
    └── attachments/   # 后续附件扩展
```

- 切换企业后仍读写同一根目录下对应企业子目录，授权一次即可。
- 企业子目录不存在时自动创建；创建失败则提示重新授权文件夹。

## 4. UI 交互设计

### 4.1 顶部标题栏右侧：企业切换下拉框

- 显示当前企业名称。
- 下拉内容：
  - 未归档企业列表，点击切换；
  - “管理企业”入口。
- 切换前二次确认，防止误切。

### 4.2 企业管理弹窗

入口：顶部下拉 → “管理企业”。

功能：

1. 新增企业：输入名称 → 创建注册表项 → 自动切换到新企业。
2. 重命名：修改企业名称。
3. 删除（归档）：
   - 当前企业不可删除，需先切换到其他企业；
   - 二次确认文案说明“仅从列表移除，本地数据仍归档保留”。
4. 已归档企业区：
   - 展示已归档企业；
   - 提供“恢复”按钮，将 `archived` 置为 0。

校验规则：

- 企业名称非空；
- 企业名称不允许重复；
- 新增/重命名失败时表单提示，不修改现有状态。

### 4.3 切换后的页面表现

- 顶部企业名更新；
- 当前路由对应页面重新加载数据；
- 侧边栏菜单高亮保留；
- 新企业无数据时显示空态/引导新建。

## 5. 配置隔离

- 按企业隔离：
  - `hr.settings`（考勤规则、提醒提前天数、社保/公积金比例、绩效等级规则、工资条配置等）
  - `hr.ui.state` 中企业相关偏好（如企业级 UI 偏好；菜单展开状态可保持全局，以具体实现为准）
- 全局共享：
  - `hr.profile`（个人资料）
  - 企业注册表与当前企业 ID

具体 localStorage 键设计：

| 键 | 范围 | 说明 |
|---|---|---|
| `hr.enterprises` | 全局 | 企业列表 |
| `hr.currentEnterpriseId` | 全局 | 当前企业 |
| `hr.profile` | 全局 | 个人资料 |
| `hr.settings` | 按企业 | 企业系统参数；可改为 `hr.settings.<enterpriseId>` |
| `hr.ui.state` | 按企业或全局 | 菜单展开等偏好，按实现需要拆分 |

## 6. 备份与恢复

- 备份入口保留在“系统设置”，只作用于当前企业。
- 导出文件结构：

```json
{
  "app": "hr_workbench",
  "enterpriseId": "ent_xxx",
  "enterpriseName": "XX公司",
  "stores": { ... }
}
```

- 恢复规则：
  - 默认恢复到当前企业；
  - 若当前企业已有数据，二次确认“会覆盖当前企业数据”；
  - 不支持跨企业合并，保持隔离边界。

---

## 7. 错误处理

| 场景 | 处理 |
|---|---|
| 切换企业数据库打开失败 | 保留当前企业不变，弹出错误提示 |
| 新增企业重名 / 名称为空 | 表单校验阻止提交 |
| 归档 / 恢复失败 | 提示错误并回滚 localStorage 状态 |
| 文件存储子目录创建失败 | 提示重新授权文件夹 |
| 删除当前企业 | 禁止，提示先切换到其他企业 |

---

## 8. 测试要点

1. 旧版本升级后，原 `hr_workbench` 数据自动归入“默认企业”，数据不丢。
2. 新建企业 A/B，切换后数据完全隔离：
   - A 新增员工在 B 不可见；
   - B 新增员工在 A 不可见。
3. 系统设置/企业相关偏好按企业隔离，个人资料全局共享。
4. 文件存储模式按 `<企业ID>/` 分目录读写。
5. 归档企业后列表消失，恢复后数据仍在。
6. 备份/恢复只影响当前企业，不污染其他企业。
7. 切换企业后各业务页面、首页统计、招聘/考勤等数据正确刷新。
8. PWA 离线、构建、文件存储模式不回归。

## 9. 不在本期范围

- 多用户 / 角色权限 / 企业级登录密码。
- 跨企业数据合并、复制、迁移工具。
- 企业级云同步 / 服务端存储。
- 企业 Logo / 主题色等品牌化配置。
